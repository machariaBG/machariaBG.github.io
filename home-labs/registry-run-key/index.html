Independent Home Lab

Registry Run Key Persistence & Process Masquerading

Lab Status: Completed Documentation: Published

Note: This is an independent home lab investigation and not a professional SOC or client incident-response experience.

Objective and Scope

To investigate and document how adversaries achieve persistence using Windows Registry Run keys, and to analyze process masquerading techniques where malicious executables disguise themselves as legitimate system binaries.

Lab Environment

  • Windows Environment (VMware)
  • PowerShell

What I Personally Did

  • Configured an isolated Windows virtual machine.
  • Used PowerShell to copy a payload and establish persistence via the HKCU\Software\Microsoft\Windows\CurrentVersion\Run registry key.
  • Executed a masquerading attack by renaming the payload to mimic a legitimate binary (calc.exe).
  • Investigated the anomalous binary by analyzing its digital signature and file details.
  • Verified the successful execution and persistence of the payload upon system reboot.

Observations and Supporting Evidence

The investigation demonstrated that relying solely on process names (e.g., calc.exe) is insufficient for threat hunting. The examined binary displayed a legitimate Microsoft signature, illustrating that attackers often copy, rename, and misuse legitimate signed software (Living-off-the-Land) to blend in. Therefore, a valid signature alone does not rule out malicious intent, and must be combined with behavioral and path analysis.

Lessons Learned and Limitations

This lab reinforced the necessity of defense-in-depth and behavioral analysis. A limitation of this isolated exercise is that it did not simulate enterprise EDR (Endpoint Detection and Response) telemetry, which would likely flag the anomalous registry modification immediately.
